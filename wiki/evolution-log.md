# Evolution Log

Record changes to the procedural wiki and the reasons for them. This log persists even when a proposed skill change is rejected or rolled back.

## 2026-09-02 — Bootstrap

- Established the two-wiki boundary: semantic specifics remain in the personal vault; procedural generalizations belong in the CoS evolution wiki.
- Established separate operational and evolution skills.
- Adapted WikiSkill's raw, wiki, and skills layers to Codex task traces, compaction, delayed outcomes, privacy, and human authorization.
- Established Codex memory as an optional hint rather than raw evidence.
- Established read-only retrieval, draft generation, and no automatic semantic capture as the initial capability envelope.

No trace-induced lessons or autonomous skill changes have been accepted.

## 2026-09-02 — First operational-contract pass

- Added `configure-chief-of-staff` as a portable configuration workflow without bundling user-specific values.
- Kept scheduling external and identified Codex `loop` as an installation-profile capability rather than CoS-owned procedure.
- Added first-pass operating, output, recurring-check, configuration, and evolution-record contracts.
- Selected inbox triage, periodic attention review, and meeting preparation as the provisional MVP workflows.
- Clarified that skill directories contain instructions and schemas while semantic facts, configured instances, operational state, raw traces, and outcomes remain outside them.

These are design-level changes and have not yet been behaviorally evaluated.

## 2026-09-02 — Raw-container policy correction

- Recast `raw` as an evidence authority and lifecycle class rather than a universal external or Git-ignored store.
- Added a per-container contract for physical distribution, versioning, update semantics, discovery, retention, privacy, disclosure, and promotion.
- Distinguished answer-scope guidance from enforceable access control: searchable content may carry a contextual or confirm-before-surface disclosure posture, but directory topology is not a security boundary.
- Recorded Readwise source Markdown and CoS trajectories as examples of raw containers with potentially different policies.
- Added Chief-of-Staff task and episode identification as an explicit Codex adapter question, with explicit invocation and scheduler markers preferred over title or content heuristics.

This correction changes the design contract; no deployed storage, task capture, or recurring monitor was created.

## 2026-09-02 — Installation-ready heartbeat and learning loop

- Made one durable task plus one native thread heartbeat the default Chief-of-Staff experience rather than a later operational enhancement.
- Preserved the portable boundary by defining recurring behavior in the skill while leaving scheduler implementation to the host.
- Added task-authored, privacy-minimized `cos-run/v1` receipts as the minimum trajectory profile for learning from the first real episodes.
- Added a separate wiki-memory adapter that generalizes procedural behavior without copying instance facts from the user's vault or live sources.
- Recast early evaluation around human-reviewed real episodes; reusable fixtures emerge when representative cases justify them.
- Added the Codex installation wrapper while retaining the portable Agent Plugins manifest.

These are explicit design policies. No user source was scanned, no task or heartbeat was created, and no operational trajectory was captured by this repository change.
