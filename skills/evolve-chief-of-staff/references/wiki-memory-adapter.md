# Wiki Memory Adapter

Use this procedure to turn Chief-of-Staff trajectories into procedural memory without turning the evolution wiki into a second personal vault.

## Inputs and Isolation

Read selected `cos-run/v1` records, linked outcome annotations, the existing evolution wiki, and the currently deployed skill. Operational Chief-of-Staff runs must not load this wiki.

Treat task-authored receipts as normalized observable evidence with known capture limitations. Treat host-enriched traces as higher-fidelity evidence, not automatically better interpretations. Do not fill gaps with Codex memory summaries or invented reasoning.

## Consolidation

1. Identify observable successes, failures, corrections, omissions, and unresolved cases.
2. Separate instance facts from reusable procedure. People, projects, messages, papers, deadlines, and their current state remain in the vault or source system.
3. Compare the candidate lesson with existing patterns and counterexamples.
4. Add or revise a scoped wiki pattern only when it follows from an explicit standing instruction or supported evidence.
5. Link protected run and outcome identifiers without copying their private contents.
6. Keep uncertainty and capture limitations visible.

A useful pattern should still make sense after substituting every current person, project, and document. It should improve how the agent retrieves, verifies, prioritizes, routes, communicates, or seeks authorization.

## Skill Proposal

Wiki maintenance does not require a skill change. When a pattern does justify one, propose one coherent, reversible patch and keep it separate from the operational skill until the user approves adoption. Use later real episodes to assess its effect; add reusable fixtures when they become valuable rather than manufacturing a test suite before use.
